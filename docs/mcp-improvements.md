# 从本次实测看 MCP 与 App 集成的优化方向

[测试经过与证据](powerbi-test-record.md) · [运行示例](../examples/powerbi-sales/README.md)

以下为依据本次 Power BI 实测提出的设计建议，**尚未实现或验证**，也不是无影官方产品承诺。描述范围为当前测试端点，不推断其他版本的能力。

## 嵌入 App 后的目标体验

上传 Excel → Agent 制作报表 → App 工作区展示真实应用 → 用户暂停 Agent 并接管 → 保存 PBIX → 下次继续编辑。

建议由客户后端负责 Agent、任务状态、权限与实例绑定；前端通过无影 SDK 呈现工作区，后端通过 MCP 操作同一个实例和登录会话。官方 Web SDK 已描述云电脑/云应用内嵌连接、输入控制、文件传输和连接事件；本仓库尚未集成 SDK。原生移动端或 WebView 的支持范围需要单独验证。[官方 Web SDK 文档](https://help.aliyun.com/zh/wuying-workspace/developer-reference/web-sdk/)

前端关闭键鼠输入不等于完整的控制权交接：服务端仍需暂停 Agent、等待正在执行的动作结束，并确认接管状态，避免双方同时操作。

## 按实测问题排序

| 优先级 | 证据或产品需求 | 建议 | 验收方法 |
| --- | --- | --- | --- |
| P0 | 文件名输入未生效，重复控件难定位 | 提供窗口/控件观察、输入、点击、等待；输入后读回结果 | 输入工具返回目标窗口、实际值与验证状态；窗口变化时停止误操作 |
| P0 | 缩放导致截图范围与坐标不一致 | 统一截图坐标，携带缩放、多屏范围和截图标识 | 在不同缩放与分辨率下点击同一目标；过期截图可识别 |
| P0 | 安装调用超时但操作实际完成 | 长任务 ID、进度查询、取消与重复请求去重 | 连接中断后查询原任务；不重复执行安装或保存 |
| P0 | App 需要人机交接，本次未测试 | 会话级控制权锁、暂停、接管与恢复 | 用户接管后 Agent 不再输入；恢复前重新观察界面 |
| P0 | shell 权限宽，多客户场景未测试 | 实例与用户绑定、应用/目录授权、短期凭据和操作审计 | 用户 A 无法访问 B 的会话和成果；凭据不进入 App 前端或日志 |
| P1 | 文件编码、校验与下载需自行编排 | 成果文件接口，返回文件 ID、类型、大小、校验值与下载权限 | App 可打开/下载成果；过期或越权请求被拒绝 |
| P1 | 首次安装与环境准备较多 | 应用环境模板、就绪检查、工作区恢复 | 记录首次可操作时间与重连恢复结果，不预设未经测量的提升百分比 |

## 工具结果应包含可验证状态

建议区分：请求已接受、正在执行、操作完成、结果验证通过、结果未知。当前启动命令仅确认文件哈希和启动请求；它不声称图表已渲染或筛选通过。

例如，“输入文件名”应报告目标窗口、控件、写入值、读回值和校验状态；“保存报表”应报告文件位置、大小、校验值与是否完成打开验证。避免将工具调用未报错等同于业务成功。

## 下一轮最小验证范围

先完成一个 App 内闭环：上传模拟 Excel、展示真实 Power BI、Agent 操作、用户接管、成果下载与重新进入。分别记录任务完成率、首次可操作时间、工具调用数、超时恢复、接管冲突和成果重开结果。当前没有这些指标的基线，也不据此计算 ROI。
